# AirPods 按压与感知：macOS 机制研究与 DSH 方案（2026-11-05）

## 1. macOS 怎么分发耳机事件
| 事件 | 机制 | 多个 App 能不能同时收 |
|---|---|---|
| 开盖、型号、左右耳和盒电量、盖子状态 | BLE 靠近配对广播（厂商 0x004C，类型 0x07；苹果没有公开接口，AirBuddy、Friday 都这么用） | 能 |
| 连接、断开、默认输入输出设备变化 | IOBluetooth 通知、CoreAudio 属性监听 | 能 |
| 按一下（播放/暂停） | AVRCP → mediaremoted → 当前占着「正在播放」的那一个 App（最后开始放声音的 App 拿到；需要注册 MPRemoteCommandCenter 并设置 playbackState） | 不能，只给一个 App |
| 通话中按柄（静音手势，macOS 14+） | `AVAudioApplication.setInputMuteStateChangeHandler`，只给正在录音并注册了这个回调的 App；没注册会弹「Cannot Control Mic with AirPods」 | 不能，只给当前录音的 App |

静音手势支持的型号：AirPods 3 代 / 4 代、所有 Pro、Max。**不支持 AirPods 1 代和 2 代。**

## 2. 主流做法
- 会议和语音类（FaceTime、AirMute→Discord）：静音手势
- 朗读、播客类（opencode-read-aloud）：只在自己出声时占用「正在播放」，读完就让出
- 听写工具（Superwhisper、Wispr Flow 这类）：键盘全局快捷键
- 定时放静音来抢「正在播放」（Friday 现在的做法）：不是标准做法，会和其他 App 互相抢

## 3. DSH 方案（待用户确认）
1. 主路线：语音模式下开麦 + 静音手势，按一下就是「开始说 / 说完」。代价是开麦期间耳机是通话音质，橙色麦克风点常亮
2. 辅助路线：DSH 用 TTS 读回复时占用「正在播放」，按一下就是打断或回复；读完马上让出，不常驻抢占
3. 兜底：键盘全局快捷键（所有设备都能用）
4. 感知：BLE 广播 + IOBluetooth + CoreAudio，跟其他 App 共存
5. 冲突检测：用 CGGetEventTapList 列出拦截媒体键的进程；用 MediaRemote 私有接口查谁占着「正在播放」；引导页指出具体是哪个 App
6. 已知坑：macOS 15.6 上 App 失焦后改不了 playbackState（Apple 论坛 799691）；Swift 6 下静音回调跑在 XPC 队列上，闭包要标 `@Sendable`

## 4. 已验证（spikes/airpods-probe，2026-11-05）
- 连接通知加 system_profiler 读型号和电量：0.1s 内拿到 0x200F（AirPods 2），左 100%、右 38%、盒 11%
- CGGetEventTapList 可以列出拦截媒体键的进程（本机只有 universalaccessd 和探测程序，都是只监听）
- 待测：AirPods 2 双击走哪条路；用一副 AirPods Pro / 3 代以上实测静音手势
