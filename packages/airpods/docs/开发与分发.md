# 耳机空间：开发与分发

## 代码在哪
`DSHub/dsh/packages/airpods/`
- `airpods-helper`：Swift 原生助手，产物是 `bin/DSH AirPods.app`，负责蓝牙、开盖卡片、录音、手势、朗读、Apple 识别、胶囊
- `speech-streaming`：流式识别注册表
- `speech-streaming-sherpa`：本地模型
- `speech-streaming-aliyun`：阿里云
- `airpods-space`：Host 插件，负责 helper 生命周期、识别轮次、指令，以及 `airpods` Remote
- `client-ui-airpods-space`：输入框上的耳机按钮、菜单、设置向导
- `airpods-space-bundle`：插件包，包括 cordis.patch.yml、图标、宣传图和 README

## 开发
```sh
cd DSHub/dsh
packages/airpods/airpods-helper/scripts/build.sh   # 改了 Swift 才需要
pnpm run build:artifacts                            # 改了 TS
DSHub/spikes/tools/restart-dev.sh                   # 重启开发版 DSH，等它就绪
npx vitest run packages/airpods                     # 单元测试
pnpm run build:check                                # 全量类型检查（打包前必须过）
```
- 开发版用的是 `apps/desktop/.desktop-build/development/home`，跟正式版的 `~/.dsh` 分开
- 调试接口：渲染进程 CDP 9222，主进程 9229。`DSHub/spikes/tools/cdp.mjs`、`shot.mjs` 可以执行脚本、截图
- 阿里云要直连：启动开发版时不要带 `NODE_USE_ENV_PROXY=1`（走代理建连要 4.5 秒，直连 0.16 秒）
- helper 用稳定的自签名证书签名（`scripts/dev-signing.sh`），重新编译后权限不会丢

## 打包正式版
```sh
NODE_USE_ENV_PROXY=1 pnpm run package:desktop:mac:arm64:unsigned   # 下载运行时需要代理
```
产物在 `apps/desktop/.desktop-build/targets/mac-arm64/unsigned-artifacts/`，里面有 dmg 和 .app。

注意事项：
- `@dshub/*` 包不能是 private，版本要跟 dsh family 一致，`scripts/release/families.ts` 放行了 `@dshub/` 前缀
- `electron-builder-config.mjs` 的 asarUnpack 包含 `@dshub/airpods-helper/{bin,assets}`；运行时 `app.asar` 的路径会换成 `app.asar.unpacked`

## 分发方式
1. **随我们的 DSH 构建内置（现在用的就是这个）**：登记在 `packages/util/official-bundles` 的 OPTIONAL、EXTENSION、EXPERIMENTAL 列表里，并加进 `apps/cli`、`apps/web` 的依赖；插件页「实验性插件」里第一个就是它。
2. **给官方 DSH 用户装**：需要把 7 个 `@dshub/*` 包发到 npm（或者私有 registry），用户在插件页「添加插件」里输入 `@dshub/airpods-space-bundle`。这是对外发布，要你确认之后才做。
3. **GitHub**：仓库公开后，「添加插件」也支持 Git 地址。同样需要你确认。
